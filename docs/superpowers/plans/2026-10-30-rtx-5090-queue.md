## Implementation sequence
1. Core MCP adapter with bounded requests, typed/validated catalog and job responses, honest errors, no submission retry on ambiguous network failure. Test against an injected transport and a local MCP server; read-only live catalog smoke.
2. Desktop Settings → Workflows: explicit queue connection check and catalog. Reachability, unavailable workflows and unchecked workflows remain distinct. Main process owns network calls; renderer receives sanitized DTOs.
3. Durable per-project queue operations: persist submission intent before dispatch, then job id, workflow/version, ordered inputs. Ambiguous dispatch must not automatically duplicate a render. Resume polling by saved id after restart. Explicit cancellation remains requested until terminal status observed.
4. Download every output before its 14-day retention expires into project-owned files with checksums. Preserve multiple outputs (including native video/audio pairs). Avoid treating a partial download as completion.
5. Register generic queue runner and wire an explicitly selected workflow into a test bundle. Add UI job status/recovery. Actual live generation acceptance uses a bounded smoke job, separate from transport/catalog verification.

## Verification and limits
Target new behavior: malformed payloads, tool errors, timeout/cancel, terminal states, unknown submission outcome, durable resume, failed/partial downloads, reference order, stale UI responses, unchecked status. Build Core and Desktop. Do not rerun unrelated previous-feature baselines. Review implementation before declaring complete. Local mocks prove contracts; only a live completed job proves generation and output retrieval.

## Durable jobs checkpoint — verified 2026-10-30

Implemented project-owned submission intent, immutable request fingerprints (ordered arrays retained), accepted remote ids, restart refresh, cancellation intent, streaming local retrieval of all outputs, SHA-256 manifests, and Desktop project controls for list/refresh/cancel/download. The ledger lives under `.dhee/gpu-queue`. Inputs and full output URLs are omitted from Desktop summary DTOs.

Submission keys identify one attempt. An interrupted or ambiguous submission never automatically creates another render. Known remote ids resume through refresh. Cross-process coordination uses proper-lockfile, plus exclusive intent creation before dispatch so a lost lease cannot overwrite another process's intent. Atomic record updates and fsync precede reported local completion. Downloads reject redirects/foreign origins and are bounded to 2 GiB per output and 120 seconds per request; these limits are explicit errors rather than partial success. Every output must be copied before phase becomes downloaded.
